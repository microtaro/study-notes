AI and trust

Can the trust that came from people reading code move to another basis?

Created 2026-11-16. Updated 2026-11-17: added the explainer “Trust in Automation.” Updated 2026-11-18: added the article explainer “How the Claude Code team does code review.” Updated 2026-11-20: added the explainer “(When) Should a Software Factory be Lights-off?” Updated 2026-11-24: added the explainer “Habituation at the Gate.”

The question

As AI writes more of the code, people can no longer read and check all of it. To trust what gets built anyway, there has to be a basis other than reading.

This theme reads papers that studied real company records and experiments, and looks at what could serve as that basis and where it falls short.

Paper explainers

  • AI Writes Faster Than Humans Can Review

    A paper on the records of a company that set out to double engineering productivity with AI, over more than two years. AI raised PR counts the longer people kept using it, but review fell behind, and AI review replaced part of human review.

    Original paper: arXiv:2607.01904v3. English version added 2026-11-16

  • Trust in Automation

    A 2004 review that organizes how far people rely on automation in terms of “trust.” When people rely on automation they cannot fully understand, trust is what guides reliance. The aim is not to raise trust but to match it to the automation's capabilities, and trust changes over time as people see how the automation behaves.

    Original paper: Human Factors 46(1), 2004. English version added 2026-11-17

  • (When) Should a Software Factory be Lights-off?

    A paper that turned real bugs people had found and fixed into review tasks, and measured how many of them AI review agents catch. The best agent caught 70% overall, including more than 60% of the bugs that had slipped through human review.

    Original paper: arXiv:2610.13668v1. English version added 2026-11-16

  • Habituation at the Gate

    A paper on how the same people review pull requests (PRs) that AI coding agents submit to open-source projects, as they review more of them. Across 11,429 reviews by 400 people, approval rose and comments fell with experience.

    Original paper: arXiv:2606.22721v1. English version added 2026-11-16

Article explainers

  • How the Claude Code team does code review

    An article in which Anthropic's Claude Code team describes how it reviews code. The team kept review but moved most of the reading to machines, and the number of human approvals, from zero to two, depends on the change's risk. AI approvals do not count as human approvals.

    Original article: claude.dev Blog (2026-10-15). English version added 2026-11-18
